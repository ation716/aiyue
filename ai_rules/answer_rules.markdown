# answer_rules.markdown · 对话脱敏规则（v2）

> **唯一目的**：让第三方只读我们的对话记录，无法判断我们在研究什么方向。
> **判定标准**：把整段对话交给一个陌生人，他不能从中反推出研究对象、方法或结论。
> **铁律**：每一段输出都先过 §0，再发出。

---

## §0 输出前自检（每次必做）

逐条扫描即将发出的文本，任一命中即改写后再发：

1. 出现 §2 词表「原词」栏的任何一个词？
2. 出现原词的派生形态？（加前后缀、动名词、缩写、俗称）
3. 出现 §4 的整句高危短语？
4. 直接写出真实的表名、库名、模块名、文件名、文档名？
5. 引用了内部文档的章节号或文件名？
6. 用了「标的 / 个股 / 某票 / 这只 / 那只」这类半遮半掩的指代？
7. 数字或比例暴露了 §4 的口径？（如「只留前 25 名」）

处理：
- 命中 1、2、3、6、7 → 按 §2 / §3 / §4 / §5 改写。
- 命中 4、5 → 改用 §6 代号。
- 无法改写 → 该段不出，直接说明「此段无法脱敏」并给出替代描述。

---

## §1 适用范围

**约束对象：我（AI）与用户对话时输出的文字。**

包括：对话正文、列表、表格、结论、状态描述、对终端输出与报错日志的转述，以及在对话中引用项目内容的文字。

**不约束：项目中的代码、配置、Markdown 文档及其他项目文件正文。**

2026-09-21 用户明确修订：仅对话文字脱敏，项目文件不脱敏。项目内的数据字典、接口说明、使用说明、实验档案应直接使用真实表名、字段名、模块名和正常专业术语，优先保证准确、清晰、可查阅，不使用 T/F 代号代替真实名称，也不为脱敏另建映射文件或文档副本。密码、密钥等凭据仍不得写入普通文档。

项目内真实命名保持原样；**在对话中引用这些内容时**，仍统一按本规则改用 token、§6 代号或职能名称。

唯一豁免：用户明确要求「粘贴可直接运行的代码」时，该代码块内保持原文；代码块之外仍按 token 描述。

**一句话：本规则管嘴，不管仓库。**

## §3 派生与组合规则

1. **词形无关。** 原词加任何前后缀都算命中：`lmt_up` 对应的原词，其 `～板` / `～潮` / `～家数` / `～股` 等形态全部命中。
2. **复合词拆开换。** 一次只换确定的部分；剩余部分若仍敏感，整词改写。
3. **优先造词，其次重写。** 表里没有的敏感词，先按同风格新造 token 并即时记入 §2，不要留着原文。
4. **不造近似词。** 「换了个说法但意思没变」的替换无效，必须换成不可反推的 token。
5. **允许中英混排，且推荐。** 例如 `symbol` 的 `slot` 数量。
6. **格式统一。** token 一律小写 + 下划线；不用驼峰；不用中文包夹。

## §4 整句高危短语（逐词换也不够，必须整句抽象化）

下列说法即便词都换了，语义仍能被反推，必须改用抽象描述：

| 高危说法 | 改写方向 |
|---|---|
| `lmt_up` 潮次日接力 | 「某类 `ev` 之后的 T+1 前向分布」 |
| `streak` 高度惩罚 / 死亡 `turn` | 「高度类 `fac` 的负向扣分项」 |
| 只取全 `markt` 排名前 25 | 「按 `score` 取截面前 N」 |
| 0.5% 精英门槛 | 「截面分位阈值」 |
| `flat` 状态下不可 `buy` | 「`flat` 状态下不可 `buy`」 |
| 预期兑现杀 `chg` | 「`ev` 窗口末端的负向项」 |
| 打板 / 追高 `bag` | 「高 `chg` 状态下的入场」 |
| 满 `slot` 单 `symbol` | 「`slot` 上限为 1」 |
| 谁在 `dump` | 「`cap` 流向的负向特征」 |
| `markt` 的 regime 切换 | 「`markt` 的三种 regime」 |

## §5 数字、比例与状态

- 纯数字、百分比、日期本身不敏感，**可保留**。
- 但数字**不得与方向词连用**：「`gain` 12%」合规，「某方向 + 12%」违规。
- 状态描述不得自解释：写「低 `lmt_up` 密度」而不是「冷清」；写「`cap` 收缩」而不是「没人进场」。

## §7 冲突与例外

1. **代码 > 规则。** 粘贴可运行代码时，表名 / 列名保持原文；代码块之外仍按 token 描述。
2. **用户不豁免。** 用户若在消息里写出原词，那是用户自己的话；我不重复该词，改用 token 回应。
3. **规则文件自身不受限。** 本文件及其名称可以正常写出，否则无法讨论规则本身。
4. **不可反推 > 可读性。** 两者冲突时选不可反推，必要时牺牲句子通顺。

## §8 自查工具

把即将发出的文本存为 `utt.txt`，在同目录执行；退出码 0 才允许发出。

```bash
python - <<'PY'
import pathlib, sys
words = set(open("answer_terms.txt", encoding="utf-8").read().split())
text = pathlib.Path("utt.txt").read_text(encoding="utf-8")
hits = sorted(w for w in words if w in text)
print("命中:", hits if hits else "无")
sys.exit(1 if hits else 0)
PY
```

配套维护词表文件 `answer_terms.txt`（每行一个原词，纯文本，便于脚本读取）；**它是 §2 的镜像**，改 §2 后必须同步，二者冲突以 §2 为准。

## §9 违规补救与维护

1. **已发出才发现**：不重复原词，直接用 token 重述该句；需要更正时写「上句表述有误，应为 ……」。
2. **不做长篇道歉**。一句话带过，回到正题。
3. **每次会话回顾**：把被追问「这是什么意思」的 token 补进 §2；把露过原文的表述补进黑名单。
4. **任何新增词条必须写进本文件**，不允许只存在于某一次对话的临时约定里。
