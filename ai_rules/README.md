# rules/ — AI 协作规则集

本目录集中存放约束 AI 在本仓库中行为的**全部**规则。让 AI 接手任何工作前，先让它读完本目录。

| 文件 | 作用 | 何时读 |
|---|---|---|
| `answer_rules.markdown` | 对话脱敏规则。约束 AI 的全部文字输出 | 每次对话，强制 |
| `answer_terms.txt` | 上表 §2 词表的纯文本镜像，供 §8 自查脚本读取 | 跑自查脚本时 |
| `experiment_trace_rules.md` | 实验追溯规则。每个 strat 一份 trace 档案 | 涉及任何 bt / 调参 / 看结果时 |
| `README.md` | 本文件，规则索引 | 进入仓库时 |

实验档案本体放在 `../traces/`，模板见 `../traces/_TEMPLATE.md`。

---

## 一分钟上手

1. 读 `answer_rules.markdown` §0，按自检清单约束每一次输出。
2. 一旦涉及实验 → 读 `experiment_trace_rules.md`，严格按其中的七步流程走。
3. 实验档案写进 `../traces/`，一节一次实验。
4. 新产物落盘到 `results/<strat-id>/<EXP_ID>/<run_id>/`；历史产物只读归档于 `results/legacy/`（明细见 `traces/_LEGACY.md`）。运行前须设有效 `EXP_ID`，否则入口脚本拒绝运行。
5. 收尾时跑一遍 §8 自查脚本。

## 硬约束速记

- 对话里**不得出现**词表原词及其任何派生形态。
- 真实表名 / 模块名 / 文档名在对话里用 §6 代号或职能名指代。
- **配置没记录 → 不许开跑；结论没写回 → 实验不算结束。**
- **脚本由用户自己执行，AI 不代跑。**
- 分析方式（自分析 / AI 分析）由用户选，AI 不替用户决定。

## 新增规则的写回要求

发现新的泄漏点、新的实验字段需求、新的反例 → 必须写回对应规则文件，不允许只存在于某一次对话的临时约定里。
