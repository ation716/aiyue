# experiment_trace_rules.md · 实验追溯规则（v1）

> **要解决的问题**：每次跑完产物目录里堆一堆文件，文件名看不出当次用了哪个数据表、哪段区间、哪些参数、和上一版的差别是什么。时间一长，没有任何一条线索能把「某个结论」和「产生它的那次运行」对上。
> **2026-09-20 重组后落地**：新产物统一写入 `results/<strat-id>/<EXP_ID>/<run_id>/`（`run_id` 含微秒防覆盖），旧历史产物整体迁入 `results/legacy/`（见 `traces/_LEGACY.md`，87 个文件 SHA256 全匹配）。
> **本规则的解法**：**一个策略一份档案，一次实验一节记录，配置先写后跑，结论不写不算完。**
> **铁律**：配置没记录 → 不许开跑；结论没写回 → 实验没结束。

---

## §0 三条门禁（不合格就停）

| 门禁 | 触发时机 | 通过条件 | 不通过时 |
|---|---|---|---|
| **G1 配置门禁** | 用户提出要跑数据之前 | 档案里已写全 §3 的**完整配置快照**，且含「与上一实验的差异」 | AI 拒绝提供运行命令，先补配置 |
| **G2 产出门禁** | 用户回报跑完之后 | 产出文件路径已**如实登记**入档案 | 不进入分析环节 |
| **G3 结论门禁** | AI 分析结束后 | 结论、证据、后续动作已**写回档案** | 该实验不得标记为「已闭环」 |

> G1 的意义：配置在跑之前写，是**预测**；跑完再补，就变成了**事后编造**，追溯价值归零。

## §1 适用范围与触发条件

**触发**：任何涉及以下动作的请求，都走本规则。

- 修改配置参数（阈值、开关、持仓数、区间、数据表、股票池）
- 改动代码逻辑（因子、打分、撮合、指标）
- 要跑回测 / 要一份结果 / 要对比两个版本
- 要分析已有产出

**不触发**：纯读代码、纯讨论设计、纯文档整理。

**关键约束（不可绕过）**：

1. **脚本由用户执行。** AI 只负责改代码、写配置、给命令、读产出。**AI 不代跑脚本**，也不把「我跑了」写进档案。
2. **分析方式由用户选。** 跑完由用户决定自分析或交给 AI。AI 不得自行认定分析已完成。
3. **档案在仓库里，不在对话里。** 对话是过程，档案是唯一事实来源。对话结束后档案仍要能被独立读懂。

## §2 目录与命名

```text
aiyue/
├── rules/
│   ├── README.md                    ← 规则索引
│   ├── answer_rules.markdown        ← 对话脱敏
│   ├── answer_terms.txt             ← 词表镜像
│   └── experiment_trace_rules.md    ← 本文件
└── traces/
    ├── _TEMPLATE.md                 ← 新档案从这里复制
    ├── aixin_full.md                ← 一个 strat 一份档案
    ├── aixin_no_risk.md
    └── aixin_herd_only.md
```

**档案命名**：`traces/<strat-id>.md`。`strat-id` 用小写 + 下划线，与代码里的 `strat` 名对齐，不要用中文、不要用日期。

**实验编号**：档案内按 `E01`、`E02`… 递增，**跨会话连续、永不重用、永不删除**。废弃的实验标记为「已废弃」而保留编号占位，否则历史引用会错位。

## §3 档案结构

一份档案 = **一个静态区** + **一个台账** + **N 个实验节**。

### 3.1 静态区（建档时写一次，之后只在策略本身变化时改）

- **策略一句话**：一句话说清它做什么。
- **核心假设**：它赌的是什么，什么情况下会失效。
- **数据依赖**：用哪些表、哪些字段、覆盖区间。
- **参数清单**：本文策略可调的全部参数，及其默认值与含义。
- **已知限制**：适合什么行情、不适合什么行情、样本有多短。

### 3.2 实验台账（每次实验追加一行）

| 编号 | 日期 | 一句话目的 | 唯一变更点 | 配置指纹 | 产出 | 分析方式 | 结论 |
|---|---|---|---|---|---|---|---|
| E01 | | | | | | | |

> **唯一变更点**列是这套流程的价值所在：一次实验只改一处，否则结果好坏归因不了。要改两处，就拆成两次实验。

### 3.3 实验节（每次实验一节，只追加，不覆盖）

每节必含以下字段，一项不落：

```markdown
### E03 · 2026-09-20 · <一句话目的>

- **假设**：这次想验证什么，预期看到什么
- **唯一变更点**：E02 → E03 只改了 `XXX`，从 A 改为 B
- **完整配置快照**：见下（全部字段，即使没变也要写，保证单节自包含）
- **数据源**：库 / 表 / 股票池 / 结束日期 / 基准 / 预热
- **代码版本**：git commit hash，或「未提交，工作区改动见备注」
- **运行环境**：解释器路径（只用代号，如 `VENV_PY`）
- **运行命令**：原样贴出，供复现
- **产出文件**：跑完后回填，如实登记全部路径
- **状态**：`待配置` / `待运行` / `待分析` / `已闭环` / `已废弃`
- **分析方式**：（跑完后回填）`用户自分析` / `AI 分析`
- **结论**：（AI 分析时必填）结论 + 支撑证据 + 不确定处
- **后续动作**：下一步做什么，或「维持现状」
```

**完整配置快照**必须逐项列出入口脚本顶部的全部可调项，缺一不可：数据源开关、画像列表、回看交易日数、初始资金、合成数据长度与种子、数据表、股票池、结束日期、基准、预热长度、画像覆盖、持仓上限、精英分位与最小放行数、单边摩擦、赔率倍数、高度安全阈值、低温禁买、事件载荷。

未使用的字段写「不适用」并说明原因（例如合成模式下的库表项），**不允许留空**。

## §4 运行流程（七步，顺序不可跳）

```text
① 建档/定位档案
      ↓
② 写配置快照 + 唯一变更点      ← G1：写全才给命令
      ↓
③ AI 给出运行命令              ← AI 不执行
      ↓
④ 用户自行执行
      ↓
⑤ 用户回报结果 → 回填产出路径   ← G2：登记才分析
      ↓
⑥ 用户选分析方式
   ├─ 用户自分析 → 用户回填结论
   └─ AI 分析   → AI 写结论与证据
      ↓
⑦ 更新台账 + 状态置「已闭环」   ← G3：没写结论不算完成
```

**AI 在各步的职责边界**

| 步骤 | AI 做 | AI 不做 |
|---|---|---|
| ① | 建档案 / 定位已有档案 | — |
| ② | 写配置、算差异 | 编造未确认的参数 |
| ③ | 给命令 | **不执行命令** |
| ④ | 等待 | 不催、不猜结果 |
| ⑤ | 登记用户回报的路径 | 不臆测产出内容 |
| ⑥ | AI 分析时给结论与证据 | 不替用户选分析方式 |
| ⑦ | 更新台账与状态 | 不在结论缺失时置「已闭环」 |

## §5 产出文件命名与落盘路径（已落地）

**重组后落盘规则**（入口脚本已实现，无需再动）：

```text
results/<strat-id>/<EXP_ID>/<run_id>/
    equity_<画像>_<模式>_<表名>_pos<N>_<MMDD_HHMMSS>_<微秒>.png
    trades_<画像>_<模式>_<表名>_pos<N>_<MMDD_HHMMSS>_<微秒>.csv
    alpha_diag_<画像>_<模式>_<表名>_pos<N>_<MMDD_HHMMSS>_<微秒>.csv
```

- **`<EXP_ID>`**：运行前必须在入口脚本顶部设 `EXP_ID = "E03"` 等有效 E 编号；未设或非 `E` 开头，脚本直接拒绝运行并退出。编号是**指针**——从路径定位到 `traces/<strat-id>.md` 的对应实验节，该节有全量配置。
- **`<run_id>`**：`datetime.now()` 精确到微秒，天然防同名覆盖。
- 文件名保留画像/模式/表名/持仓数，区间与其余参数以实验节为准，不塞进文件名（容量与可读性考量）。

**机制说明**：实验编号的强制绑定已由入口脚本的 `EXP_ID` 门禁保证，目录层级即指针，因此无需再把编号拼进文件名（§5 旧方案的「改文件名」步骤已用「目录指针」取代，更简洁）。

## §6 关于「乱」的根因诊断

历史 `output/`、`output_d400/`、`output_smoke/`、`aixin/output/` 曾积压 87 个文件，乱在三处，本规则逐条对应：

| 根因 | 表现 | 对应条款 |
|---|---|---|
| 配置不在文件里 | 文件名无区间、无阈值，事后无法复现 | §5 编号指针 + §3 配置快照 |
| 无实验编号 | 同名靠时间戳区分，时间戳本身无意义 | §5 `EXP_ID` 门禁 |
| 两套命名并存 | 早期无模式标签的文件与后期带模式的混放 | §7 历史归档 |

## §7 历史产出的归档要求（已执行）

历史文件**不得删除**，已与新的编号体系隔离：

1. 四层重组（2026-09-20）已把 `output/`、`output_d400/`、`output_smoke/`、`aixin/output/` 整体机械迁入 `results/legacy/<原相对目录>/`，**不删不覆盖**，每文件源/目标双 SHA256 校验一致（87/87 匹配）。
2. 登记见 `traces/_LEGACY.md`：区分合成模式与真实链路（`stock_daily_kline_20220101_1314`）产物；**能确认的写确认，不能确认的明确写「来源不可考」**，未编造配置或结论。
3. 此后新产物只写入 `results/<strat-id>/<EXP_ID>/<run_id>/`，不再落入 `results/legacy/`。

> 不要把来源不明的结果当证据用。这比文件乱更危险。

## §8 违规补救

| 情况 | 处理 |
|---|---|
| 跑完才发现配置没记 | 立即补记，并在该节显式标注「配置为事后补记，可信度低于常规记录」 |
| 一次改了多处 | 结果不得归因于单一变更；台账「唯一变更点」列写「多处变更（见备注）」 |
| AI 分析结论未写回 | 该实验状态**停留「待分析」**，不得进入下一实验的对比 |
| 发现档案与代码不一致 | 以代码为准修正档案，并在结论里说明曾不一致 |

## §9 与 answer_rules 的关系

两份规则**同时生效、互不覆盖**：

- `answer_rules.markdown` 管 AI 在**对话里怎么说**。
- 本文件管 AI 在**仓库里怎么记**。

因此：档案本体（`traces/*.md`）按仓库常规写法即可，**不做脱敏**；但 AI 在对话中引用档案内容时，仍须按 `answer_rules` 换成代号与 token。
