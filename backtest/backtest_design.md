### 一、先纠正容易造成虚假成交的口径

1. **区分委托类型与成交价格。** 建议把现有“条件买单/卖单”明确为“触价委托”：`trigger_price` 是触发门槛，不一定是成交价；再单列 `execution_price_policy`。开盘/尾盘若按竞价撮合，买单在 `auction_price <= trigger_price`、卖单在 `auction_price >= trigger_price` 时，原则上按该时点价格成交，但还必须通过涨跌停、现金、可卖数量等检查。“没有超过涨停/没有小于跌停”应同时约束条件价和拟成交价；委托价本身若越界，不能因为当日价格后来回落就默认其为合法委托。尾盘是用收盘价代理收盘集合竞价成交价，并非证明当时真实可成交。
2. **涨跌停价不能直接由前复权日线计算后当作真实委托价。** 当前数据库日线价格为前复权口径，真实涨跌停价以当时未复权参考价和适用规则为基础；除权除息、复牌等日期还可能有特别口径。仅有前复权 OHLC 时，可保留 `ROUND_HALF_UP(prev_close * 1.10/0.90, 2)` 为“近似限制价”，并在结果标注 `limit_price_quality=approx_adjusted`；不能把代理值用于声称精确判定。若未来取得历史未复权价、参考价及状态数据，再升级为精确模式。涨跌幅自行计算，但应同时保留前收盘价、计算公式及精度。
3. **`high == close` 不是“封死涨停”的充分条件，`low == close` 也不是“封死跌停”的充分条件。** 它们只是形态，可能发生在非涨跌停日。建议先判断是否触及可核验的限制价，再判定 `close == limit_up/down`；即便收盘封住，也不能由日线推知盘中封单顺序和委托队列。当前规则“封死时只要 low < open / high > open 就可成交”同样不能证明条件价触发前有可执行流动性。建议默认保守拒单并给出 `UNVERIFIABLE_QUEUE`，或设成显式的乐观假设开关，分别输出敏感性结果。
4. **盘中区间穿越不等于按条件价成交。** `low < trigger_price < high` 只证明价格区间覆盖，不证明触发先于另一笔委托，也不证明该价有可用量。若保留日K代理，应写清“触价即以触发价成交、忽略订单簿和路径”的强假设；当日同一 OHLC 同时满足多个互斥条件时必须固定优先级或拒绝推断，不能用当日收盘结果倒推盘中决策。等于 low/high 的边界当前严格不成交，应维持显式配置，不混用 `<=`。
5. **主板不等于所有日期均适用 10%。** 需按交易当日状态筛选，特别是 ST、*ST、上市初期、复牌或其他不设常规涨跌幅限制的日期。现有资料尚不能可靠还原历史状态；遇到无法核验的日期，默认标记 `RULE_UNKNOWN` 并拒绝按“真实可成交”计入，或只允许在明确开启近似模式后参与，结果单列。不要以当前名称反推历史状态。

### 二、建议补全执行约束与时间顺序

- 单日阶段固定为 `PRE_OPEN -> OPEN -> INTRADAY -> CLOSE -> EOD`；同阶段卖后买只是确定性的模拟约定，不是日K能证明的真实先后。盘中卖出的现金默认到下一阶段才可用于买入，避免日内路径穿越；开盘卖出所得能否用于同一开盘买入需单独约定。
- 信号携带 `generated_at`、`earliest_execution_phase`，任何阶段只能读取当时已知的信息：昨日收盘生成的计划可在今日开盘执行；今日完整 OHLC、当日成交量/额、当日评分不得用于今日开盘或盘中生成交易决策。若用当日盘后数据产生信号，最早下一交易日执行。
- A 股普通股票按 T+1 的**可卖数量**管理：今日买入进入 `today_bought_qty`，下个交易日才转为 `sellable_qty`；卖单量不得超过可卖数量。将证券可卖限制与卖出所得现金可用限制分开建模。
- `open/high/low/close` 缺失或非正、`low > high`、`open/close` 不在区间内、同代码同日重复记录时拒绝撮合并记录数据原因；缺日不推断为停牌，也不造价格。前复权价格仅可用于同口径信号和估值演示，现金结算、整数股数、实际费用和除权除息若要准确处理，需要未复权成交价及公司行为数据。
- 资金约束至少覆盖 `available_cash`、`reserved_cash`、`frozen_cash`；部分成交、撤单、委托有效期（建议默认当日有效）、费用计提时点、100 股整数手及卖出零股、滑点、税费、股利拆合都要明确。若暂不具备成交量分布，默认“全额成交”是可选假设，不要把日成交量当作开盘或尾盘可成交量。
- 日终权益定义为 `cash_total + sum(quantity * valuation_price)`；估值价缺失时沿用最近有效价格且打 `stale_price` 标记，过久缺失可拒绝给出可信的总权益。不得用未知价格填 0，也不强制将无法卖出的持仓在期末变现。

```python
from dataclasses import dataclass
from datetime import date
from decimal import Decimal
from typing import Literal

@dataclass(frozen=True)
class CandidateSignal:  # 选股策略逐项返回；可为空列表
    signal_id: str                 # 稳定唯一编号，用于追溯
    ts_code: str                   # 与 DailyBar.ts_code 使用同一规范
    generated_date: date           # 产生信号的日期，必须早于执行日
    side: Literal["BUY", "SELL"]  # 卖出决策可由独立风控/退出策略产生
    rank: int | None = None        # 买入候选的确定性次序；不可依赖当日完整K线
    score: Decimal | None = None   # 可选，不要求跨策略分数可比
    reason: str = ""               # 信号出处/规则标识，不作为撮合输入

@dataclass(frozen=True)
class AllocationItem:  # 分仓模块逐项返回；表示预算，不等于已成交
    plan_id: str
    signal_id: str
    ts_code: str
    side: Literal["BUY", "SELL"]
    generated_date: date
    trade_date: date
    phase: Literal["OPEN", "INTRADAY", "CLOSE"]
    budget: Decimal | None = None       # BUY: 最多占用现金，含预计佣金；SELL 时为 None
    target_quantity: int | None = None # SELL: 拟卖数量（受可卖数量约束）；BUY 时由转换层计算

@dataclass(frozen=True)
class AllocationPlan:
    plan_id: str
    generated_date: date
    items: tuple[AllocationItem, ...]  # 即使无入选项也返回空 tuple
    unallocated_cash: Decimal          # 暂未分配的当前阶段可用现金
```
