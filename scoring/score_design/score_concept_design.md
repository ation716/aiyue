## 1. 设计目标

### 1.1 目标

按当前概念映射，将成员的日涨幅聚合为概念层面的日涨幅，并在统一交易日历上计算：

- 每日等权概念涨幅；
- 每日流通市值加权概念涨幅；
- 累计统计序列；
- 固定长度窗口涨幅；
- 可选的流通市值分层独立结果；
- 可选的相邻等长窗口比较结果。

本模块用于描述概念成员集合的价格变化，不等同于可直接交易的投资组合收益，也不用于直接判定产业景气周期。

### 1.2 当前交付边界

| 内容 | 当前状态 |
|---|---|
| 每日等权 | 已实现 |
| 每日流通市值加权 | 已实现，默认使用当日流通市值 |
| 每日有效成员子集 | 已实现，按方法分别筛选并重新归一化 |
| 缺口后的成员复现衔接 | 已实现，本地日线缺口按停牌处理 |
| 累计统计序列 | 已实现，整体无效日后不自动重启 |
| 固定窗口涨幅 | 已实现，默认40个交易日，不移动窗口 |
| 整个概念无数据日补值 | 已按确认口径实现前三日EWM方向，真实全区间验证待完成 |
| 流通市值分层 | 已实现独立层结果，综合层间权重未定义 |
| 环比比较 | 已实现为显式研究选项 |
| 爆发阶段识别 | 尚未定义触发、确认、解除和合并规则 |

## 2. 数据来源与边界

### 2.1 数据来源

| 数据 | 必要字段 | 用途 |
|---|---|---|
| 概念映射 | `concept_name`, `ts_code` | 建立概念与成员关系 |
| 日线长表 | `ts_code`, `trade_date`, `close` | 计算成员日涨幅 |
| 日线长表 | `float_mv` | 流通市值加权及分层 |
| 日线长表 | `vol`, `amount` | 识别当日存在交易活动 |

数据字段单位和连接方式沿用数据模块定义。本文不新增数据表，不在数据库连接层写入聚合逻辑。

### 2.2 数据使用原则

1. 只使用真实数据库或用户提供的真实数据。
2. 不构造人工、随机或模拟数据作为业务验证依据。
3. 同一计算过程中的收盘价必须来自同一复权版本；模块不主动进行复权变换。
4. 概念成员使用当前映射，不还原历史时点成员名单；结果不宣称消除历史成员变化或幸存者偏差。
5. 日历使用来源长表日期并集，并按日期升序、唯一化后作为统一日期轴。
6. 窗口按统一日期轴计数，不按每个成员各自最近若干条记录计数。

### 2.3 不属于本模块的内容

以下内容不作为本版前置计算条件：

- 历史成员有效区间还原；
- 最小成员数门槛；
- 覆盖率筛选；
- 额外缺失治理报表；
- 交易成本、滑点、成交约束和资金曲线；
- 爆发阶段的最终业务判定。

这些边界不代表可以静默伪造数值。空集合、必要字段缺失、零分母和非有限结果必须保留明确状态。

| 符号 | 含义 |

## 4. 日期对齐与成员日涨幅

### 4.1 统一日期面板

对每个概念建立：

```text
概念成员 × 统一交易日历
```

成员在某个统一日期没有日线记录时，该位置保留为空，不删除日期，也不向前寻找另一日期来替代当前日期。

### 4.2 连续有效记录

正常相邻有效日的成员日涨幅为：

```text
r(i,t) = P(i,t) / P(i,t-1) - 1
```

要求：

- 当前收盘价和前一个有效收盘价均为正；
- 当前记录状态可参与计算；
- 分母不为零；
- 结果为有限数值。

内部保存小数比例，展示层再转换为百分比。

### 4.3 本地日线缺口按停牌处理

用户已确认：本地数据中成员缺少日线记录的情况按停牌处理。

处理规则：

1. 缺口日期不作为该成员的有效参与日；
2. 缺口后的首条有效记录使用缺口前最后一条有效收盘计算；
3. 连续缺口不填成零涨幅；
4. 其他成员仍按当日可用情况参与概念聚合；
5. 复现日的成员日涨幅可以跨过停牌区间，但只跨越该成员自己的缺口，不跨越概念整体无结果日。

例如：

```text
最后有效收盘 → 多个缺口日 → 首条有效记录
```

复现日使用：

```text
首条有效记录收盘 / 缺口前最后有效收盘 - 1
```

### 4.4 交易活动与状态表

- `vol > 0 AND amount > 0` 只能证明当日存在交易活动，不能单独证明其他日期或其他成员停牌。
- 如果传入真实状态表，字段为 `ts_code`、`trade_date`、`is_suspended`。
- 明确停牌成员仅退出当天；明确正常成员可以参与。
- 状态与正交易记录发生直接冲突时，输入应报错。
- 当前正式口径优先使用本地日线缺口规则；外部状态表仍属于可选输入。

## 5. 概念日涨幅聚合

### 5.1 B口径：每日有效成员子集

当前采用 B 口径：

1. 每天、每种方法分别筛选必要字段有效的成员；
2. 缺记录或未知状态的成员不作为当天参与者；
3. 不把未知成员自动判定为停牌；
4. 不为缺失成员填零涨幅；
5. 剩余成员重新归一化权重；
6. 空集合由后续整体补值规则处理；
7. `member_count`记录实际参与数量，`member_scope`记录是否为完整映射或有效子集。

因此，结果描述的是“当天有效成员子集的概念统计”，不代表完整映射成员集合在当天的完整表现。

### 5.2 方法一：每日等权

令 `A(c,t,equal)` 为当天可用成员集合：

```text
N(c,t) = |A(c,t,equal)|

r_equal(c,t) = Σ[i∈A(c,t,equal)] r(i,t) / N(c,t)
```

每个有效成员对当天结果的权重相同。没有有效成员时不生成真实等权结果。

### 5.3 方法二：当日流通市值加权

用户已确认使用当日流通市值进行当日描述统计，不使用总市值，也不要求改用前一日市值：

```text
w_mv(i,t) = M(i,t) / Σ[j∈A(c,t,float_mv)] M(j,t)

r_mv(c,t) = Σ[i∈A(c,t,float_mv)] w_mv(i,t) × r(i,t)
```

要求：

- `M(i,t)` 为有限正数；
- 权重分母为正；
- 市值缺失的成员退出当日市值方法；
- 市值方法不因某成员市值缺失而自动切换为等权；
- 当日权重是事后描述统计，不解释为当日开盘前已经知道的可交易权重。

### 5.4 成员范围字段

| 字段 | 含义 |
|---|---|
| `member_count` | 当前方法当天实际参与的成员数 |
| `member_scope=full_mapping` | 当天参与数等于该概念去重后的完整映射数 |
| `member_scope=valid_subset` | 当天只使用必要数据有效的成员子集，空集合也属于此范围 |

不同方法可能因市值字段要求不同而使用不同成员集合，因此两种方法的结果差异不能全部归因于加权公式。

## 6. 整体无数据日补值

### 6.1 触发范围

用户确认：如果整个概念当天都没有数据，进行补值；不移动窗口。

该规则只针对概念整体没有可用聚合结果的日期，不把单个成员停牌、单个成员字段缺失或某个分层为空自动等同于整个概念无数据。

当前代码已加入补值方向，但触发范围、边界状态和新版全区间验证仍需收尾核对。正式实现应保留原始状态与补值状态，不能把补值结果伪装成真实聚合结果。

### 6.2 固定日期和窗口

补值不改变日期轴：

- 不删除整体无数据日；
- 不跳过缺失日；
- 不向更早日期扩展以凑够40个有效日；
- 每个目标日仍按统一交易日历最近40个日期计算窗口；
- 补值日参与窗口连乘，但必须能被单独识别。

### 6.3 补值方法

用户确认的方向为：使用前三日指数平滑；不足三日时沿用前值。

当前实现具体采用：

```text
最近三个历史日变化的 EWM(span=3, adjust=False)
```

边界规则：

1. 至少有三个历史日结果时，使用最近三个历史日变化做指数平滑；
2. 历史结果不足三个但存在前值时，沿用最近前值；
3. 前面完全没有可用历史值时仍为空，不凭空生成；
4. 补值状态使用 `daily_status=imputed_ewm3`；
5. 记录 `imputation_method` 和 `imputation_source_count`；
6. 补值不代表真实成员聚合结果。

“前三日”的最终工程实现需要严格区分：是最近三个有效结果，还是统一日期轴上紧邻的前三个日期。当前代码使用历史有限值序列，属于已知待整理项，不在本文将其描述为已完成验证。

## 7. 累计序列与固定窗口

### 7.1 累计序列

对已定义方法：

```text
I_m(c,t0) = 1
I_m(c,t) = I_m(c,t-1) × [1 + r_m(c,t)]
```

约定：

- 第一日期的1.0是归一化锚点，不代表该日已有真实聚合值；
- 方法未定义时，不建立有效锚点；
- 概念整体无结果且无法补值时，累计序列中断；
- 当前不自动分段重启累计；
- 累计中断后，后续窗口仍可在数据足够完整时恢复。

### 7.2 固定窗口涨幅

默认窗口长度 `L=40`：

```text
R_m(c,t,L) = Π[k=t-L+1..t] [1 + r_m(c,k)] - 1
```

要求：

- 使用固定日期窗口，不移动日期以寻找40个有效日；
- 窗口内存在不可计算日且未被确认补值时，窗口结果为空；
- 窗口内使用补值时，结果应保留补值标识；
- 窗口计算不等同于从累计序列直接取比值，尤其是在累计序列已经中断而窗口重新恢复时；
- 40日窗口需要40段日变化，首段不足时状态为 `window_insufficient`。

### 7.3 状态

| 状态 | 含义 |
|---|---|
| `valid` | 当前结果按真实有效成员计算完成，且数值有限 |
| `empty_members` | 当前方法当天没有可用成员，尚未或不能补值 |
| `imputed_ewm3` | 当前日结果来自确认的补值规则，不是真实成员聚合 |
| `method_undefined` | 方法所需配置未定义，例如市值时点为 `None` |
| `nonfinite_result` | 计算结果为无穷或其他非有限值 |
| `window_insufficient` | 日期轴起始位置尚未形成完整窗口 |
| `window_contains_invalid_day` | 窗口长度已达到要求，但窗口内仍有不可用日 |
| `anchor_only` | 累计序列的约定起点，不代表有效日结果 |
| `unavailable` | 累计或窗口结果当前不可用 |

最终 `status` 不替代 `daily_status`、`window_status` 和 `index_status`。查看结果时应先判断日结果，再判断窗口和累计状态。

## 9. 接口与结果结构

### 9.1 数据加载接口

```python
load_concept_inputs(db, concepts, start_date, end_date, preheat_days=1)
```

其中：

- `db` 是已打开的只读数据连接；
- `concepts` 是概念名称列表；
- `start_date`、`end_date` 是目标区间；
- `preheat_days=1` 默认只多取前一个统一日期，供日涨幅参考；窗口初期可以不足。长缺口可能仍找不到此前有效收盘，不保证一天覆盖所有边界。
- 这是加载策略，不是接口1内部预热。接口1仅计算传入数据；接口2需要更长窗口历史时由调用方显式指定，不能重新隐式多取81天。
- 迁移注意：旧第5参数为window_size，新第5参数为preheat_days，已有调用应改用关键字，不能把旧WINDOW直接传入。

返回：

```text
members, daily, calendar
```

如果该接口在读取成员映射时发生数据库超时，后续日涨幅和周期接口尚未执行；应先按数据库读取问题处理，不能把该报错归因于 DataFrame 聚合或窗口计算。

### 9.2 计算接口

接口1只计算概念日涨幅：

```python
calculate_concept_daily_returns(
    members,
    daily,
    calendar,
    *,
    method="equal",
    mv_timing="current",
    suspensions=None,
)
```

接口1返回每个概念、日期、方法的 `daily_return` 及其日状态、实际成员数量和补值字段；不计算累计序列、固定窗口和环比字段。

接口2只根据接口1返回的日涨幅计算周期结果：

```python
calculate_concept_periods(
    daily_returns,
    window_size=40,
    *,
    research_comparison=False,
)
```

接口2不访问数据库、不重新聚合成员，只生成 `index_value`、`window_return` 及可选的相邻窗口比较字段。这里的“周期”指累计序列和固定窗口统计，不等同于尚未定义的爆发阶段识别。

原组合入口 `calculate_concept_returns(...)` 保留名称，内部按顺序调用接口1和接口2，但不是完整旧参数兼容：默认改为equal，旧research_layers参数已移除，改用method。

## 10. 入口与调试约束

### 10.1 两阶段调试

入口仍保持简短、断点友好，但计算步骤明确分为：

1. 配置参数并从真实数据源加载 `members`、`daily`、`calendar`；
2. 调用接口1，得到 `day_result`，先查看概念日涨幅和每日参与成员数；
3. 调用接口2，得到 `result`，再查看累计序列和固定窗口；
4. 最后截取 `shown` 作为目标区间展示结果。

接口1和接口2均不打印、不主动抛出业务断言、不构造样本。接口2不访问数据库，便于单独判断耗时来自数据读取、日涨幅聚合还是周期计算。函数内部保留必要输入保护。参数注释说明日期范围、窗口、市值时点、分层和比较开关的含义。

## 11. 验证与追溯

## 12. 设计决策摘要

当前正式口径可概括为：

```text
当前概念映射
    ↓
统一日期轴对齐
    ↓
成员日涨幅计算
    ↓
每日按方法筛有效成员
    ↓
等权／当日流通市值加权
    ↓
概念整体无数据日按确认方向补值
    ↓
累计序列与固定40日窗口
    ↓
可选分层和环比研究
```

核心原则：

- 日历固定，窗口不为缺失日移动；
- 部分成员缺数据不阻断其他有效成员；
- 整个概念无结果时按确认的补值规则处理，但必须保留补值标记；
- 缺口后的成员复现日可以使用停牌前最后有效收盘；
- 累计序列不自动分段重启；
- 未定义规则不伪造为已完成算法；
- 未完成真实验证的边界不宣称已经通过。
